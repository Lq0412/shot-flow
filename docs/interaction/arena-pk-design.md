# 擂台 A/B 对决交互设计

> 片刻的核心创新——"两两对决"替代传统列表/网格浏览

## 为什么擂台模式更好

传统选片工具（Aftershoot/Narrative/FilterPixel）都是列表或网格模式，用户在缩略图中找最好的。

**擂台模式的核心优势：**
- 每次只需做 1 个二元决策（左 or 右），认知负担最低
- A/B 对比天然适合"哪张更好"的判断
- 手势操作（左右滑）比点击网格快 3-5 倍
- 游戏化体验，有"淘汰赛"的紧张感和成就感

## 交互设计

### 基本布局

```
┌──────────────────────────────────┐
│  第 1 组/共 5 组   第 3 轮/共 7 轮  │  ← 顶部信息栏（半透明）
├────────────────┬─────────────────┤
│                │                 │
│                │                 │
│    照片 A      │     照片 B       │  ← 左右各占半屏
│                │                 │
│                │                 │
├────────────────┴─────────────────┤
│   [ 选左边 ]        [ 选右边 ]    │  ← 底部操作按钮
└──────────────────────────────────┘
```

### 手势系统

| 操作 | 效果 |
|------|------|
| 点击左侧照片 | 选左边 |
| 点击右侧照片 | 选右边 |
| 左滑手势 | 选左边（右侧照片跟手滑出） |
| 右滑手势 | 选右边（左侧照片跟手滑出） |
| 双指缩放 | 放大查看细节 |
| 长按 | 显示 EXIF 信息面板 |
| 滑动 < 50dp 松手 | 弹回取消选择 |
| 滑动 ≥ 50dp 松手 | 确认选择 |

### 鸿蒙原生实现要点

```typescript
// 手势组合
.gesture(
  GestureGroup(GestureMode.Exclusive,
    // 左右滑动选择
    PanGesture({ fingers: 1, direction: PanDirection.Horizontal })
      .onActionEnd((event) => {
        if (Math.abs(event.offsetX) > 50) {
          this.makeDecision(event.offsetX > 0 ? 'right' : 'left')
        }
      }),
    // 双指缩放
    PinchGesture()
      .onActionUpdate((event) => {
        this.zoomScale = event.scale
      })
  )
)
```

### 选择反馈动画（0.5 秒）

1. 赢家：放大至 1.05x + 绿色边框扩散
2. 输家：缩小至 0.95x + 灰度化
3. 0.3s 后双图向屏幕外滑出
4. 0.5s 后新对决从两侧滑入

### 快捷键（鸿蒙平板适用）

| 按键 | 效果 |
|------|------|
| ← | 选左边 |
| → | 选右边 |
| ↑ | 保留全组（不淘汰） |
| ↓ | 淘汰全组 |
| Z | 撤销上一步 |
| 1-5 | 星级评分 |

## 竞技场配对算法

采用淘汰赛制：
1. 同一组内的照片随机配对
2. 每轮淘汰一半
3. 直到每组只剩 1 张冠军照片
4. 如果某组照片数量不是 2 的幂，部分照片首轮轮空

## AI 辅助标记

- 每组中综合评分最高的照片预标记为"AI 推荐"
- 有技术问题的照片（轻微模糊、偏暗）显示小标签
- 不强制选择 AI 推荐的，仅作参考

## 撤销机制

- 支持逐步撤销（最近一步）
- 支持重新打开整个组（重做整组对决）
- 撤销栈限制最近 50 步（避免内存爆炸）
