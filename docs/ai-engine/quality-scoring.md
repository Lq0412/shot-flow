# 多维画质评分思路

> AI 如何判断一张照片"好不好"

## 问题

需要自动判断哪些照片有技术问题（模糊、曝光、闭眼），哪些画质更好。

## 评分维度

### 专家模式评分

| 维度 | 模型/方法 | 权重 | 说明 |
|------|----------|------|------|
| **美学评分** | NIMA + MUSIQ + CLIP-IQA 三模型融合 | 50% | 三模型归一化后取加权平均 |
| **主体锐度** | 人脸区域 > 显著性区域 > 全图 | 20% | 优先评价主体清晰度 |
| **人脸质量** | InsightFace 锐度 + 眼睛开合度 + 裁切 | 15% | 仅人像照片 |
| **技术基线** | 拉普拉斯方差 + FFT 高频比 | 15% | 基础画质检查 |

### 极速模式评分（零模型依赖）

| 维度 | 方法 | 说明 |
|------|------|------|
| **模糊检测** | 拉普拉斯方差 + Tenengrad + FFT 高频比 | 三种方法交叉验证 |
| **运动模糊** | 方向性模糊检测 | 区分"整体软"和"运动模糊" |
| **曝光检测** | 9 宫格直方图分析 | 检测局部过曝/欠曝 |
| **主体锐度** | 显著性区域提取 + 边缘宽度分析 | 先找主体再评锐度 |
| **边缘宽度** | Marziliano 算法 | 边缘越宽 = 越模糊 |

## Fatal Flags（致命标记）

某些问题严重到直接标记为"不建议保留"：

| Flag | 检测方法 | 惩罚 |
|------|---------|------|
| **闭眼** | InsightFace EAR (Eye Aspect Ratio) | -1.5 |
| **严重模糊** | 拉普拉斯方差 < 极低阈值 | -1.2 |
| **严重过曝** | > 80% 像素饱和 | -0.8 |
| **严重欠曝** | > 80% 像素接近 0 | -0.8 |
| **裁切人脸** | 人脸紧贴边缘 | -0.5 |

**Fatal Flag 机制**：多个 flag 必须达到阈值才自动淘汰（"陪审团投票"），避免单一误判导致淘汰。

## 综合评分公式

```
composite = normalized_aesthetic × 0.50
          + subject_sharpness × 0.20
          + face_quality × 0.15
          + technical × 0.15
          + Σ(fatal_flag_penalties)
```

### 归一化

所有子评分归一化到 0-10 分：
- NIMA 原始输出 1-10，直接用
- MUSIQ 原始输出 0-100，除以 10
- CLIP-IQA 原始输出 0-1，乘以 10
- 拉普拉斯方差通过训练集统计映射到 0-10

### 三模型美学融合

```
aesthetic = 0.40 × NIMA + 0.35 × MUSIQ + 0.25 × CLIP_IQA
```

**为什么三个模型**：单一美学模型有偏好偏差。NIMA 擅长构图，MUSIQ 擅长技术质量，CLIP-IQA 擅长语义理解。融合后更鲁棒。

## 主体锐度的优先级

```
1. 检测人脸 → 人脸区域锐度（最重要，人眼最关注人脸清晰度）
2. 无人脸 → 显著性区域锐度（找到画面主体）
3. 无显著主体 → 全图锐度
```

**洞察**：整张照片锐度不重要，重要的是"主体清不清楚"。一张背景虚化的人像照片，全图锐度可能很低，但人脸很清晰——这其实是好照片。

## 踩过的坑

1. **美学分高 ≠ 好照片**：NIMA 对色彩鲜艳的照片给高分，但可能是严重模糊的彩色照片。必须和锐度交叉验证。

2. **背影误杀**：背影/侧脸照的"眼睛开合度"低，被误判为闭眼。需要先判断是否为正面，非正面不检测闭眼。

3. **合影复杂性**：10 人大合照，一个人闭眼不应该淘汰整张。需要更灵活的策略（如"主角色"检测）。

4. **极浅景深**：f/1.2 拍的人像，耳朵和头发一定模糊。只评价对焦平面上的区域。

## 对云端 API 的建议

```
评分应返回结构化数据：
{
  "composite": 7.2,
  "aesthetic": 8.1,
  "sharpness": 6.5,
  "face_quality": 7.0,
  "technical": 7.8,
  "flags": ["slight_blur"],           // 轻微问题标记
  "fatal_flags": [],                   // 严重问题标记
  "auto_reject": false,                // 是否建议淘汰
  "reject_reason": null                // 淘汰原因
}
```

这样鸿蒙端可以灵活展示，而不是只给一个总分。
