# 多信号融合分组思路

> 桌面版最核心的 AI 算法——将相似照片归组的思路

## 问题

摄影师一次拍摄产生大量连拍照片（几十到几百张），需要将"同一瞬间"的照片归为一组，然后在组内选最好的。

## 解决方案：多信号融合 + 自适应权重

### 信号来源

| 信号 | 来源 | 说明 |
|------|------|------|
| **语义相似度** | DINOv2 (384 维向量) | 理解照片内容，两张构图相似的照片向量接近 |
| **人脸身份** | InsightFace ArcFace (512 维) | 同一组人出现在不同照片中 |
| **拍摄时间** | EXIF DateTime | 连拍间隔通常 < 2 秒 |
| **GPS 位置** | EXIF GPS | 同一地点拍摄 |
| **文件名编号** | 文件名解析 | IMG_2048 和 IMG_2049 很可能是连拍 |
| **感知哈希** | pHash/dHash/wHash/aHash | 像素级相似度（极速模式） |
| **颜色直方图** | HSV 直方图 | 颜色分布相似 |
| **几何验证** | ORB + RANSAC | 验证两张图是否从近似视角拍摄 |

### 自适应权重（核心创新）

权重不是固定的，而是根据照片内容动态调整：

```
# 人像模式（两张都有人脸）
face_overlap:    0.50   ← 人脸匹配最重要
dinov2:          0.20   ← 语义相似次要
time:            0.15
exif:            0.10
gps:             0.05

# 风景模式（没有人脸）
dinov2:          0.35   ← 语义相似最重要
time:            0.25
exif:            0.20
color:           0.10
gps:             0.10

# 信号缺失时的权重重分配
GPS 缺失 → gps 权重分配给 EXIF 和 time
没有人脸 → face 权重分配给 dinov2 和 time
```

**关键洞察**：固定权重在信号缺失时表现差。自适应权重让系统在信息不完整时仍然可靠。

### 两阶段聚类

**阶段一：强制连拍分组**

```
条件：文件名编号相邻 + 拍摄时间间隔 < 阈值
结果：这些照片必须在一组（不进聚类算法）
```

**阶段二：软相似度聚类**

```
使用完整链接聚类（Complete Linkage）
- 计算所有照片对的相似度
- 相似度 > 阈值的照片合并
- 用 Complete Linkage：组间距离 = 两对照片中最大距离
- 防止单链接的"链式连接"问题（A-B-C-D 被连成一串）
```

### 极速模式 vs 专家模式

| 维度 | 极速模式 | 专家模式 |
|------|---------|---------|
| 分组信号 | 4 种哈希 + HSV + ORB | DINOv2 + 人脸 + 时间 + GPS + 文件名 |
| 模型依赖 | 无 | DINOv2-Small + InsightFace |
| 处理速度 | ~50ms/张 | ~200ms/张 (CPU) |
| 精度 | 日常够用 | 专业级 |
| 内存占用 | ~200MB | ~2-3GB |

## 聚类算法选择

### 为什么用 Complete Linkage（完全链接）

```
单链接（Single Linkage）：
  组间距离 = 最近两对的距离
  问题：A↔B 相似、B↔C 相似、C↔D 相似 → A,B,C,D 全进一组
       但 A 和 D 其实完全不同！→ "链式连接"

完全链接（Complete Linkage）：
  组间距离 = 最远两对的距离
  优点：组内所有照片两两相似，不会出现链式连接
  代价：可能分出更多小组（但这对选片是好事）
```

**选片场景下的直觉**：宁可多分几组，也不要把不相关的照片混在一起。用户在小组里选照片比在大组里快得多。

## 云端 API 分组流程

```
鸿蒙端上传缩略图 + EXIF 数据
    ↓
云端提取特征：
  - DINOv2 向量（384 维）
  - 人脸嵌入（512 维 × 人脸数）
  - 时间戳
  - GPS（如有）
    ↓
计算所有照片对的融合相似度
    ↓
两阶段聚类
    ↓
返回分组结果
```

## 对鸿蒙 App 的意义

分组质量直接决定擂台体验。分组不好会出现：
- 不同场景的照片被放在一组 → 用户困惑
- 同一连拍被拆成两组 → 重复选片

**经验值**：分组正确率需达到 90%+（同一连拍序列的 90% 归入同组），否则用户会频繁手动调整。
