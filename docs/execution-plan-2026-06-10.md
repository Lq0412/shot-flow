# Shot Flow 极简执行计划

> 创建时间：2026-06-10
> 目标：2026-09-30 前上架华为应用市场
> 开发方式：AI Coding（Cursor/Claude Code 驱动开发，不手写每一行）
> 约束：每天 1-2 小时（晚上/周末）

## 现实约束

| 因素 | 情况 |
|------|------|
| 每日时间 | 1-2 小时（晚上/周末） |
| 开发方式 | AI Coding（Cursor + Claude Code） |
| ArkTS 经验 | 零，但通过 AI 辅助可快速实现 |
| 预估周期 | **8-10 周**（AI coding 加速，比纯手写快 2-3 倍） |
| 目标 | 上架 + 拿激励金 + 秋招简历亮点 |

## 核心原则

1. **能上架的最小产品 > 功能丰富但没上架的半成品**
2. **AI 写代码，我做产品决策和验收**
3. **每天至少 commit 一次，链条不能断**

上架版本只需：
1. 能导入照片
2. AI 帮你筛掉明显废片（模糊/曝光）
3. 好照片之间能 A/B 对比选择
4. 能导出选好的照片

## Phase 1：本地初筛（Week 2-3 | 6.17 - 6.30）

**目标：能自动标记出模糊/过曝的废片**

| 周 | 任务 | 产出 |
|---|------|------|
| Week 2 | AI 实现图片清晰度检测 + 曝光检测（Worker 线程） | 每张图有评分 |
| Week 3 | 初筛结果页 UI：废片展示 + 批量确认/恢复 | 用户能审核筛选结果 |

**技术选择**：
- 全部设备端本地处理
- 算法让 AI 基于鸿蒙 image API 实现（PixelMap 像素操作）
- 如果鸿蒙原生 API 不够用，降级为最简单的亮度/对比度检测

**✅ Week 3 验收**：导入 50 张 → 自动标出废片 → 确认后剩余好照片进入下一步。

| 周 | 任务 | 产出 |

**✅ Week 6 验收**：照片自动分组 → 每组淘汰赛 → 选出 Winners。

## 执行纪律系统

### 最小承诺（不可违反）

> **每天至少打开项目 + commit 一个东西。**
>
> - 好的一天：推进了一个完整功能
> - 普通的一天：修了一个 bug / 调了 UI
> - 差的一天：改了一行注释也 commit
> - ❌ 唯一不允许：一整天没碰项目

### 3 天规则

> **如果连续 3 天没 commit → 第 4 天必须坐下来至少做 30 分钟。**
>
> 不管做什么，打开项目、commit 一个东西，把链条续上。
> 链条一旦断超过一周，项目大概率就死了。

### 防跑偏规则

- 刷推特看到新想法 → 记到 `ideas-inbox.md` → 不动手
- 想给 Shot Flow 加新功能 → 记到 Issue → 上架后再做
- 想重构/优化架构 → 上架前不允许重构，能跑就行

### 每周日自检

- [ ] 这周有几天 commit 了？（目标：≥5 天）
- [ ] 有没有一个可验证的新进展？
- [ ] 下周要做什么？（写 3 个具体任务）
- [ ] 有没有被新想法诱惑过？抵抗住了吗？

## 风险与应对

| 风险 | 应对 |
|------|------|
| AI 生成的代码在鸿蒙上跑不通 | 换一种实现方式让 AI 重写；极端情况降级功能 |
| 图片处理 API 鸿蒙不支持 | 用最基础的 PixelMap 像素操作代替 |
| 中间失去动力 | 看看已完成的 commit 记录，告诉自己"已经做了这么多了" |
| 审核被拒 | 缓冲期足够（6周），修改后重提 |
| 想加新功能 | 写到 Issue，上架后再说 |

## AI Coding 使用策略

### 每次开发会话的流程

```
1. 明确今天要做什么（一个具体功能点）
2. 给 AI 清晰的上下文（当前代码 + 目标 + 鸿蒙 API 文档链接）
3. AI 生成代码 → 模拟器验证 → 不对就让 AI 修
4. 跑通了 → commit → 结束
```

### 给 AI 下指令的原则

- 每次只做一个小功能，不要一次生成整个模块
- 给 AI 参考：华为官方示例代码 / Codelab / API 文档
- 明确告诉 AI 目标平台是 HarmonyOS 5.0+、ArkTS、ArkUI
- 代码不用完美，能跑就行，上架后再优化
