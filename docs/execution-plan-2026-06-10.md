# Shot Flow 极简执行计划

> 创建时间：2026-06-10
> 目标：2026-09-30 前上架华为应用市场
> 约束：每天 1-2 小时（晚上/周末），ArkTS 零基础

## 现实约束

| 因素 | 情况 |
|------|------|
| 每日时间 | 1-2 小时（晚上/周末） |
| 每周有效时间 | ~10-12 小时 |
| 总可用时间 | 6月10日 → 9月30日 = 16 周 ≈ **160-190 小时** |
| ArkTS 经验 | 零，需要学习期 |
| 目标 | 上架 + 拿激励金 + 秋招简历亮点 |

## 核心原则

> **能上架的最小产品 > 功能丰富但没上架的半成品**

上架版本只需：
1. 能导入照片
2. AI 帮你筛掉明显废片（模糊/曝光）
3. 好照片之间能 A/B 对比选择
4. 能导出选好的照片

## Phase 1：本地初筛功能（Week 3-5 | 6.24 - 7.14）

**目标：能自动标记出模糊/过曝的废片**

| 周 | 任务 | 产出 |
|---|------|------|
| Week 3 | 实现图片模糊检测（Laplacian 方差计算）| 每张图一个清晰度分数 |
| Week 4 | 实现曝光检测（直方图分析）+ 综合评分 | 自动标记"建议删除"的照片 |
| Week 5 | 初筛结果页 UI：展示废片 + 一键确认/恢复 | 用户能审核 AI 筛选结果 |

**技术选择**：
- 全部设备端本地处理，不做云端
- Worker 线程跑图像处理，不阻塞 UI
- 算法用最简单的：Laplacian 方差 + HSV 直方图，不上模型

**✅ Week 5 验收**：导入 50 张照片 → 自动标出模糊/过曝 → 用户确认删除 → 剩余好照片进入下一步。

---

## Phase 2：A/B 擂台 PK（Week 6-9 | 7.15 - 8.11）

**目标：核心交互——两张照片对比选最佳**

| 周 | 任务 | 产出 |
|---|------|------|
| Week 6 | 简单分组逻辑（按时间相近分组） | 照片按连拍序列自动归组 |
| Week 7 | Arena 基础 UI：左右两张图 + 点击选择 | 能进行 A/B 对比 |
| Week 8 | 淘汰赛逻辑 + 进度状态管理 | 每组选出一张最佳 |
| Week 9 | 打磨动画/手势 + 进度保存恢复 | 流畅体验 + 进程恢复 |

**设计决策**：
- 只做 Arena 一种模式
- 不做偏好学习
- 不做同步缩放
- 手势只做最基本的左右滑动选择

**✅ Week 9 验收**：选完照片 → 每组有一个 Winner → 所有 Winner 组成最终结果集。

## 明确不做的功能（v2 再说）

| 功能 | 砍掉原因 |
|------|---------|
| 云端 AI（Expert/Tycoon Mode） | 需要部署服务器，增加复杂度和成本 |
| 偏好学习系统 | 好但不是 MVP 必须 |
| XMP 导出 | 专业功能，普通用户不需要 |
| RAW 文件支持 | 太复杂，先只支持 JPEG/HEIF |
| 三种工作流模式 | 只做 Arena 一种 |
| 同步缩放对比 | 非核心交互 |
| 团队协作/分享 | 用户量起来再做 |
| SD 卡直读 | 硬件依赖，优先级低 |

## 每周自检

每周日晚上问自己：

- [ ] 这周写了代码吗？（不是文档/规划）
- [ ] 有没有一个新功能能跑了？
- [ ] 下周要做什么，清楚吗？

**连续两周答案是 No → 停下来复盘原因，不要闷着拖延。**

## 风险与应对

| 风险 | 应对 |
|------|------|
| ArkTS 学习曲线比预期陡 | Week 1-2 如果搞不定 PhotoPicker，花一整个周末集中突破 |
| 实习占时间 | 工作日实习，晚上 1h + 周末 4-5h 推进 |
| 图片处理在鸿蒙上性能差 | 用缩略图（300px）做处理，不处理原图 |
| 9.30 前做不完 | 只要"导入→初筛→Arena→导出"能跑通就提交，水印砍掉也行 |
| 又想加新功能 | 写到 ideas.md，不动手。上架前只做计划内的东西 |

## 最低上架标准（底线）

如果时间实在不够，只要满足以下条件就提交审核：

- [x] 能从相册导入照片（JPEG/HEIF）
- [x] 能自动筛除模糊/过曝废片
- [x] 能进行 A/B 对比选择
- [x] 能导出 Winners 到相册
- [x] 有隐私政策和用户协议
- [x] 不崩溃

水印、设置页、最近记录——都是加分项，不是必须项。
